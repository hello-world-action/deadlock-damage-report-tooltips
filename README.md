# Damage Row Tooltips — a Deadlock HUD mod

Adds the game's own ability and item tooltips to the rows of the **Incoming Damage** report
(the table on the right of the screen when you die). Hover a row and you get the same tooltip
you'd see for that ability or item elsewhere in the game, for the enemy who hit you.

Last worked on: 2026-11-15, against Deadlock client version 6861 (`steam.inf`, dated Nov 09 2026).

## Current state

**Working and installed.** Confirmed in a live match:

| Row type | Behaviour |
|---|---|
| Hero abilities (signature, ultimate, innate) | Game's ability tooltip, using the attacking player's slot so their upgrades and numbers show |
| Items | Game's item tooltip, always for player slot 0 (see Known limits) |
| Guns, melee, troopers, guardians | No tooltip |

What is currently changed on this machine outside this folder:

- `…\Deadlock\game\citadel\gameinfo.gi` has the addons search path added. Original saved next to it
  as `gameinfo.gi.bak` (and in `vanilla\gameinfo.gi.orig`).
- `…\Deadlock\game\citadel\addons\pak50_dir.vpk` is the mod.
- Deadlock's Steam launch options may still contain `-condebug` (writes `game\citadel\console.log`).
  Only needed for debugging; safe to remove.

To undo all of it: `.\tools\install.ps1 -Uninstall`.

## Everyday commands

Run from this folder, **with Deadlock fully closed**:

```powershell
.\tools\gen_data.ps1      # regenerate the ability/item/hero tables AND the layout from the installed game
.\tools\build.ps1         # compile mod\ and pack build\damage_row_tooltips_dir.vpk
.\tools\install.ps1       # patch gameinfo.gi (once, with backup) and copy the VPK into addons
.\tools\install.ps1 -Uninstall
```

If PowerShell refuses to run scripts: `powershell -ExecutionPolicy Bypass -File .\tools\<script>.ps1`.

When to run what:

- **A patch adds heroes or items** → `gen_data`, `build`, `install`. Until then, new abilities have no tooltip.
- **A patch resets `gameinfo.gi`** (mod stops loading) → `install`.
- **You changed anything under `mod\`** → `build`, `install`.
- The game only loads the mod at startup; restart Deadlock after every install.

## How the mod works

1. **Override one layout.** The game builds each damage row from the `AbilityDamageBar` snippet in
   `panorama/layout/hud_damage_rows.xml`. The mod ships its own copy of that file, identical
   except that it includes two scripts. A file in `citadel/addons` overrides the same path in the
   game's `pak01`.
2. **Find the rows.** The game creates each row with the id `AbilityDamage_<key>`, where `<key>`
   is the ability or item class name (`citadel_ability_hornet_leap`, `upgrade_toxic_bullets`) —
   or a display name for NPCs (`T1 Guardian`). The script polls `#Data` every 0.25 s and attaches
   `onmouseover` / `onmouseout` handlers to rows it hasn't seen.
3. **Decide what the row is.** `$.DamageRowTooltipKinds[key]` is `'a'` (ability), `'i'` (item) or
   missing (no tooltip). Generated from `m_eAbilityType` in `abilities.vdata`.
4. **Find the attacker's player slot** (abilities only). `$.DamageRowTooltipHeroes[key]` gives the
   owning hero (`hero_hornet`), from `m_mapBoundAbilities` in `heroes.vdata`. The script localizes
   `#hero_hornet` and looks for a top-bar panel `TopBarPlayer<slot>` whose `.HeroName` label
   matches. The number in that id is the player slot. Falls back to slot 0.
5. **Show the tooltip** by dispatching the game's own events:
   - abilities: `CitadelShowAbilityDetailsTooltip(token, slot)` / `CitadelHideAbilityDetailsTooltip()`
   - items: `CitadelShowModTooltip(token, slot)` / `CitadelHideModTooltip(token, slot)`

   `token` is the **numeric hash** of the key: MurmurHash2 of the lowercased name, seed
   `0x31415926` (Valve's `CUtlStringToken`). The script computes it in `token()`.
6. **Hide reliably.** The currently shown tooltip is tracked in `$.DamageRowTooltipCurrent` and
   closed before any new hover is handled, so rows without a tooltip don't inherit the last one.

Set `DEBUG = true` at the top of `damage_row_tooltips.js` to log every hover with a `[DRT]`
prefix. With `-condebug` in the launch options the log is at
`…\Deadlock\game\citadel\console.log`.

## Things learned the hard way

Worth reading before changing anything.

- **Layouts are compiled to a binary AST** (`.vxml_c`, "LaCo" block), not embedded source. They
  need Source 2 Viewer to read and the CSDK `resourcecompiler.exe` to write. CSS (`.vcss_c`) and
  JS (`.vjs_c`) still embed their source.
- **CSDK 13 has no VPK packer**, so `build.ps1` writes the VPK (v2, single `_dir` file) itself.
- **In mod source, includes point at the compiled names**: `s2r://…/foo.vjs_c`, `…/foo.vcss_c`.
- **The tooltip events reject an ability name passed as a string** from script
  ("Event arguments could not be parsed"). They accept the numeric token hash.
- **Event strings on panels are treated as JavaScript**, both from `CreatePanelWithProperties` and
  from layout XML in a file that has scripts, when the game can't parse the arguments — so
  `onmouseover="CitadelShowModTooltip(upgrade_x, 0)"` fails with "is not defined". Dispatch from
  script with `$.DispatchEvent` instead.
- **`CitadelShowReadOnlyAbilityDetailsTooltip` (5 args) cannot be called from script** at all;
  its hero-id / enum arguments don't parse. Use the 2-argument per-player event.
- **Never do work when the script loads.** The HUD, including this layout, is created at game
  startup. A diagnostic that created game panels (`CitadelAbilityIcon`, `AbilityDetailsPanel`, …)
  at load made Deadlock crash on launch three times. The script now only starts its polling loop
  at load; everything else happens on hover, inside try/catch.
- **If the game won't launch after an install**, delete `…\game\citadel\addons\pak50_dir.vpk`
  (or run `install.ps1 -Uninstall`). Crash dumps land in `…\Deadlock\game\bin\win64\*.mdmp`.
- **`Image` panels have no readable source** from script (`SetImage` only), which is why the
  attacker is derived from the ability rather than read from the row's hero icon.
- **`evsig.ps1 -Dump -Names <Event>`** shows an event's registration in `client.dll`: the argument
  count is the value loaded into `r8d` (`41 b8 NN` or `45 33 c0` for zero), and the nearby strings
  are its description and first argument name. Its non-dump mode (guessing argument *types* from
  nearby vtables) proved unreliable — ignore it.

## Known limits

- **Item tooltips use player slot 0.** An item's name doesn't identify its owner, and the row
  exposes nothing else readable, so item numbers may not reflect the attacker's stats.
- **Abilities not bound to exactly one hero** (and any hero missing from the top bar) also fall
  back to slot 0.
- **New heroes / items need a regenerate + rebuild** before their rows get tooltips.
- **The mod carries a copy of the damage-row layout.** If a patch changes that layout, the old
  copy overrides the new one until the mod is regenerated (`gen_data.ps1`) and rebuilt.
- **If Valve renames the tooltip events or the `TopBarPlayer<n>` panels**, tooltips silently stop
  (or use slot 0). Nothing in the mod can prevent that.

## Publishing (in progress)

Decision made 2026-11-15: publish it (GameBanana, which is also Deadlock Mod Manager's store).

Done:

- **Runtime fallback for unknown keys** (`kindOf()` in `damage_row_tooltips.js`): a key missing
  from the generated table is treated as an item if it starts `upgrade_`, as no-tooltip if it
  contains weapon/melee/gun/npc/trooper, otherwise as an ability. Known guns/melee are now in
  the table as `'x'` so they stay excluded.
- **Layout is generated**, not hand-kept: `gen_data.ps1` decompiles the game's current
  `hud_damage_rows`, injects the `<scripts>` block, and stops with an error if the vanilla
  layout's structure has changed.
- **`tools\release.ps1 -Version x.y.z`** writes `release\DamageReportTooltips_v<x.y.z>.zip`
  (the VPK as `pak50_dir.vpk` plus a `README.txt`).

## Open ideas (discussed, not built)

1. **Patch-robustness**
   - One `update.ps1` plus a "Play Deadlock" shortcut: compare `steam.inf` `ClientVersion` with
     the version last built for; if it changed or `gameinfo.gi` lost the search path, regenerate,
     rebuild, reinstall, then launch via `steam://run/1422450`.
2. **Deadlock Mod Manager packaging**
   - The built VPK can be imported as is: Mods Library → Add Local Mod (accepts `.vpk`, `.zip`,
     `.rar`, `.7z`; only a name is required). The manager handles `gameinfo.gi` itself.
   - Run `install.ps1 -Uninstall` first so the mod isn't loaded twice.
   - The manager won't run the build scripts, so a packaged copy relies on the runtime fallback
     above for new heroes/items, and still needs a manual rebuild if the layout changes.
   - A public listing means uploading to GameBanana (the manager's store is its catalog).
     GameBanana's submission requirements have not been looked up yet.
   - Undecided: personal use only, or publish.
3. **Attacker slot for items** — no approach found yet. One untested idea: when the report is
   filtered to a single hero (the `DamageBy_<hero>` columns), all rows belong to that hero.
